Produces one review file per work at `data/preliminary-reviews/<slug>.md`. The point of this skill is to judge the work on its own terms *first* — as if reviewing it for a stranger with no idea what this reader likes — and only bring in personal taste at the end. A review that leads with taste-fit is doing a worse, lazier version of this task; the craft judgment has to stand on its own before it gets colored by preference.

## Hard constraints

- **No chapter-by-chapter breakdown.** Never structure the output as "Chapter 1: ... Chapter 2: ...". Synthesize across the whole work into thematic/argument-driven sections. If a background agent is used to extract notes from a long work (see below), its chapter-by-chapter notes are raw material to synthesize from, not a structure to preserve into the final review.
- **Face value before taste.** Sections 1–4 below must be written as if the taste profile doesn't exist. Only section 5 onward may reference `data/taste-profile.md` or `data/taste-profiles/*.md`. If taste-profile language leaks into the earlier sections (e.g. judging a slow-burn negatively just because the reader doesn't want one), that's a bug — put it in section 5 instead.
- **Deviation from canon (fan-works only) is neutral until argued.** Never treat "this isn't how the source portrays the character" as a defect on its own. The question is internal consistency: does the portrayal follow coherently from what's been changed (setting, backstory, circumstance), or does it contradict itself / exist only to enable a convenient plot beat? Blackbird relocates its cast to 1940s Berlin with zero connection to the source's actual setting and is excellent, because the characters' core facets survive the transplant intact. Ozymandias writes a Zuko who behaves very differently from canon book-1 Zuko, and it's still praised, because that difference is earned by a changed circumstance (years in a prison camp, no Avatar-hunt lifeline) rather than asserted for convenience. Use this as the test, not "how much does it match the show."
- **Two-part verdict, not one score.** The final verdict must separately answer: (a) is this a good/well-crafted story, on its own merits, and (b) is this the kind of story this particular reader would probably like. These can and often will diverge — say so plainly when they do, rather than collapsing to a single number.

## Process

1. **Read the work.** For a work already in `data/texts/<slug>/`, read every chapter file directly if the total length is manageable in-context. For a long work (roughly 80k+ words) or a work fetched fresh from AO3/elsewhere, it's fine to dispatch a background `Agent` to do close reads of chapters/sections and report back detailed notes with verbatim quotes — but brief it explicitly: extract quotes and observations for *synthesis*, not a chapter recap, and call out anything relevant to prose style, characterization consistency, dialogue voice, structural choices, and (if applicable) canon deviation. Do at least the opening and closing chapters yourself directly so your own judgment of tone and ending craft isn't secondhand.
2. **Check completion status** if the work is a fan-work on AO3 or similar (word count vs. a "Complete"/"WIP" marker, chapter count vs. stated total). This matters for how the ending gets judged — an abrupt or open ending in a confirmed-ongoing WIP is not a craft failure; the same ending in a work marked Complete is fair game to critique as the author's final, deliberate choice. State which case applies before judging the ending.
3. **Write the standalone review** (sections 1–4, no taste-profile references):
   1. **Overview / what kind of book this is.** A couple sentences of orientation — form, structure, POV, scale — enough that the rest of the review makes sense to someone unfamiliar with the work. Note any structural quirks up front (anthology-of-oneshots vs. through-composed novel, unusual tense/POV, epistolary sections, etc.) if they shape how the rest of the review should be read.
   2. **Prose and craft.** Sentence-level quality, dialogue voice differentiation between characters, use of restraint vs. told-not-shown emotion, object/action correlatives, structural devices and whether they're used with purpose or just for novelty, pacing. Quote directly — a claim about prose quality needs a quoted line backing it, not just an assertion.
   3. **Characterization.** Internal consistency is the test, always — for original characters as much as fan-work ones. Do characters remain recognizable through change, or does change happen because the plot/genre needs it to (convenient softening, flattened antagonists, growth that erases what made someone who they were)? Name specific scenes/lines as evidence either way.
   4. **Canon deviation (fan-works only).** Where does it diverge from source material, and does that divergence hold together on its own terms? Apply the Blackbird/Ozymandias test above. Skip this section entirely for original fiction.
   5. **Ending craft.** Judge as its own axis, informed by the completion-status check from step 2.
4. **State a standalone verdict** before moving on: is this simply a well-made piece of fiction, independent of whether this particular reader would enjoy it? This is the checkpoint — write this sentence explicitly before starting section 5, so the taste layer that follows is visibly built on top of it rather than blended in.
5. **Layer in taste-profile fit.** Now read/reference `data/taste-profile.md` and any relevant files in `data/taste-profiles/`. Cover: fit against the corpus's cross-story throughlines, an explicit anti-profile checklist (told-not-shown, miscommunication-as-engine, flanderization/whump-service, fragmented narration, spectacle escalation, cost-free wish-fulfillment, flattened side characters — pull the current list from the taste profile rather than hardcoding it here, it evolves), and anything from a case-study file that applies.
6. **Similar works.** Name specific works from the user's corpus (or elsewhere, if relevant and known) this one resembles — in premise, in a specific technique, or in a specific failure mode — and say plainly if one of them does the same thing better. This is about placing the work in context, not padding.
7. **Final verdict — two parts, stated separately:**
   - *Is this a good story?* (craft verdict, independent of taste — should read as a natural continuation of step 4, not a contradiction of it)
   - *Is this a story this reader would probably like?* (taste-fit verdict, may diverge from the craft verdict in either direction — a well-made story can still be a pass on taste, and a rougher one can still be a strong personal fit)

## Output

Save to `data/preliminary-reviews/<slug>.md` (slug matches the `data/texts/<slug>/` directory name where applicable, otherwise a short kebab-case title). Title the file `# Preliminary Review: <Title> (<author>)`. Mention the saved path to the user when done; don't paste the whole review into the chat unless asked — summarize the verdict and let them open the file.

This file is meant to persist and be referenced later, not just read once — it's the deep craft analysis backing whatever quick `good`/`bad` flag and note the user eventually leaves via the UI's review modal (written to `data/texts/<slug>/review.json`). Two consequences:

- **Before writing a new preliminary review**, check whether `data/preliminary-reviews/<slug>.md` already exists. If it does, treat it as prior work to update/reconcile rather than silently overwrite — note explicitly what changed (new chapters posted, revised judgment, etc.) if the content materially differs from before.
- **`taste-profiler`** should be checked/updated to read a matching `data/preliminary-reviews/<slug>.md` (if present) as high-signal input when profiling a `good`-flagged story, alongside the `review.json` note — the preliminary review is a much deeper read than a one-line note and shouldn't go unused once the user forms their real verdict.
